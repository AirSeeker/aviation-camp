# Aviation Camp: повний опис проєкту

Цей документ описує проєкт як цілісну систему: вебзастосунок для навчання за посібниками FAA, локальні дані, конвеєр обробки PDF, генерацію уроків і перевірки. Фактичні підрахунки нижче відповідають файлам у репозиторії на момент створення цього опису.

## 1. Призначення й загальний потік

Aviation Camp збирає навчальну бібліотеку з авіаційних посібників FAA. Вміст зберігається у файлах, а Next.js під час збірки перетворює уроки на статичні сторінки. Для підготовки контенту передбачений окремий Python-конвеєр:

```text
PDF + chapters.json
        |
        v
scripts/parse_pdf.py
        |  витягнутий текст, маніфести, зображення
        v
resources/parsed/<book>/ + public/images/<book>/
        |
        v
scripts/generate_content.py (Gemini API або fallback)
        |
        v
src/content/docs/<book>/*.mdx
        |                              content/quizzes/<book>/*.json
        +------------------------------+
                       |
                       v
          Next.js: npm run build
                       |
                       v
        out/ статичний сайт + індекс пошуку
```

Перші п'ять кроків є конвеєром підготовки/оновлення навчального матеріалу. Звичайний перегляд сайту читає вже наявні MDX, JSON і локальні зображення; він не викликає Gemini та не потребує серверної бази даних.

## 2. Поточний склад даних

| `Instrument` | Instrument Flying Handbook | 11 |

| `WeightBalance` | Aircraft Weight and Balance Handbook | 10 |

У репозиторії також є 7 PDF-джерел, 126 `content.md` у parsed-дереві, 3 032 зображення, 101 JSON-банк із 311 питаннями, 4 словникові терміни та 4 абревіатури. Кількість parsed-файлів охоплює не лише глави, а й окремі секції/додатки. PDF виключені з Git через `.gitignore`; для повторного запуску парсера потрібні локальні вихідні PDF.

Короткі коди книг є частиною маршрутизації та назв каталогів. Для нової книги треба узгоджено додати її в `src/content/subjects.ts`, об'єкт назв у `scripts/verify_pages_export.mjs`, а також забезпечити каталоги вихідних даних і маніфестів.

## 3. Вебзастосунок

### Технології та режим запуску

- Next.js 14 App Router, React 18, TypeScript зі strict-режимом.
- MDX відображається через `next-mdx-remote/rsc`; іконки — `lucide-react`; стилі — власний CSS у `app/globals.css` із Tailwind/PostCSS у конфігурації.
- `next.config.js` вмикає `output: 'export'` і `trailingSlash`. `npm run build` створює статичний сайт у `out/`, який призначений для статичного хостингу, зокрема GitHub Pages. Це не серверний застосунок із динамічним API.
- `basePath` у production за замовчуванням формується з назви репозиторію в `GITHUB_REPOSITORY`; його можна перевизначити через `NEXT_PUBLIC_BASE_PATH`. Локально за замовчуванням префікса немає. Цю змінну слід узгоджено задавати для build і postbuild.

### Сторінки й маршрути

| Шлях | Призначення |
| --- | --- |
| `/` | Каталог семи посібників, дев'яти PPL-категорій, пошук і прогрес читання. |
| `/subjects/<book>/` | Список статичних уроків конкретного посібника. |
| `/subjects/<book>/<chapter>/` | Урок: MDX-текст, PDF-діапазон джерела, зображення, озвучення, позначка завершення та квіз. |
| `/exam/` | Таймерований пробний іспит PPL. |
| `/glossary/` | Алфавітний список термінів та абревіатур із двох JSON-файлів. |

Сторінки посібників і глав перелічуються через `generateStaticParams`; `dynamicParams = false` означає, що невідомі шляхи не генеруються динамічно. Головна сторінка має дев'ять тематичних категорій PPL, кожна з яких веде до відповідного посібника:

- Air Law → `PHAK`;
- Human Performance → `RiskManagement`;
- Meteorology → `Weather`;
- Communications → `InstrumentProcedures`;
- Principles of Flight і Operational Procedures → `AFH`;
- Flight Performance and Planning → `WeightBalance`;
- Aircraft General Knowledge → `PHAK`;
- Navigation → `Instrument`.

Маршрути `/exam/` і `/glossary/` реалізовані, але поточний головний екран не містить явних посилань на них. Відкрити їх можна за прямою адресою.

### Як утворюється урок

`src/content/subjects.ts` перелічує підтримувані книги й читає MDX із `src/content/docs/<book>/`. Заголовок та інші значення frontmatter читаються простими регулярними виразами. Назва й діапазон PDF-сторінок беруться з `resources/parsed/<book>/book_manifest.json`.

Frontmatter уроку має містити `title`, `description`, `subject`, `chapterNumber`, `readTimeMinutes`, `lang` і `translationKey`. Вміст після frontmatter компілюється як MDX. Під час відображення сторінка:

1. шукає банк `content/quizzes/<book>/<chapter>.json`;
2. читає `images_manifest.json`; новий парсерний вивід уже містить фігури в текстовому потоці, а для старих MDX без вбудованих посилань застосовується приблизний розподіл за сторінкою джерела;
3. додає для зображення підпис/номер сторінки та перевіряє, що файл існує в `public/images`;
4. рендерить `<Quiz />` із відповідним банком; якщо компіляція MDX не вдається, використовує спрощений текстовий fallback.

Уроки використовують англомовний контент і голос `en-US`. Картинки зберігаються локально; відсутній файл не ламає сторінку, а замінюється повідомленням про недоступну ілюстрацію.

### Клієнтські функції та збереження

- `LibrarySearch` завантажує `search-index.json` лише після відкриття вікна пошуку. Пошук — нечутливе до регістру входження підрядка у назву книги, номер глави або текст; показується до 12 результатів. Є клавіатурне скорочення Ctrl/Cmd+K.
- `Quiz` зберігає вибрані відповіді, результат і час проходження в `localStorage`. Відправлення квізу також додає урок до переліку завершених.
- `StudyProgress`/`LessonCompletion` зберігають список завершених уроків і результати квізів у ключі `aviation-camp:study-progress`. Стан локальний для цього браузера/сховища: облікового запису, синхронізації між пристроями чи серверного сховища немає.
- `ExamMode` працює на клієнті: 30 хвилин, прохідний бал 70%, пояснення й посилання на джерело після завершення. Поточний модуль імпортує `content/quizzes/ppl/aerodynamics.json`, у якому зараз 3 питання; це не випадкова вибірка з усіх 311 питань.
- `VoiceReader` і озвучення запитань використовують вбудований у браузер Web Speech API. Функція залежить від підтримки браузера та встановлених голосів; текст уроку не надсилається зовнішньому сервісу озвучення.

## 5. PDF-парсер

Основний файл — `scripts/parse_pdf.py`. Він використовує PyMuPDF і проходить такі етапи:

1. Знаходить PDF у `resources/library`; `--book` обмежує запуск одним каталогом.
2. Відкриває та перевіряє документ; виявляє різні PDF, що мали б записатися в той самий каталог книги.
3. Визначає діапазони глав. Пріоритет: локальний `chapters.json`; інакше legacy-мапа `resources/library/chapter_overrides.json`; якщо ні того ні іншого немає, книга пропускається.
4. Для конфігурованої книги може окремо витягнути `glossary`, `acronyms`, `emergencyProcedures` і named appendices.
5. Витягує текст сторінками, зберігаючи порядок колонок і фільтруючи повторювані колонтитули/текст із фігур без OCR реконструкції.
6. Витягує зображення, класифікує підписи/фігури, дедуплікує повторне використання й записує місця розташування.
7. Спочатку готує тимчасовий набір файлів, потім публікує його; є rollback при невдалому оновленні, очищення за попереднім маніфестом і кеш за PDF та налаштуваннями.

`chapters.json` використовує номери сторінок PDF з 1, включно з обома межами. Діапазони мають бути валідні й упорядковані, глави не повинні перекриватися; проміжки між явно заданими главами допустимі. Приклад структури та докладні правила є в `README_parser.md`.

CLI:

```bash
python scripts/parse_pdf.py [--book AFH] [--workers 4] [--chapter-overrides PATH]
```

Якщо книга не має `chapters.json` і не задана через `chapter_overrides`, вона пропускається замість автоматичного розбиття.

## 6. Генератор MDX

Основний файл — `scripts/generate_content.py`. Він читає маніфест і `content.md` (legacy fallback — `content_raw.txt`) із `resources/parsed`, передає текст і метадані доступних зображень у Gemini та записує MDX у `src/content/docs/<book>/`. Якщо тексту немає, API не налаштований, запит вичерпав спроби або результат не проходить перевірку, генератор має перейти до шаблонного fallback. Цей fallback не є рівноцінною AI-редактурою: він бере не більше шести перших абзаців і додає загальні навчальні блоки.

Для API рекомендуються `GEMINI_API_KEY` або `GOOGLE_API_KEY`; модель задається `GEMINI_MODEL`, якщо не використовується значення за замовчуванням. `.env` не додається до Git. Виклики повторюються до трьох разів із затримкою для тимчасових помилок/квот.

```bash
python scripts/generate_content.py [--book PHAK] [--dry-run] \
  [--serial] [--delay-seconds 5]
```

`--dry-run` показує глави/metadata без запису. `--serial` додає паузу між главами. Не запускайте генерацію без наміру оновити MDX: команда перезаписує файли-результати для оброблених глав.

## 7. Формати контенту

### Урок MDX

Файл — `src/content/docs/<Book>/<chapter>.mdx`. Frontmatter містить заголовок, опис, назву предмета/посібника, номер глави, орієнтовний час читання, мову `en` і стабільний `translationKey`. Тіло — Markdown/MDX. Сам квіз у звичайному випадку позначений `<Quiz />`; конкретні питання завантажуються з відповідного JSON-файлу.

### Банк квізу

`content/quizzes/<Book>/<chapter>.json` — непорожній масив. Кожне питання має `id`, `question`, щонайменше дві `options`, індекс `correctAnswer` з нуля, `explanation` і `reference` з `book`, `chapter`, `anchor`. `scripts/verify_quizzes.mjs` перевіряє структуру, межі індексу, пояснення, посилання та унікальність ID у всіх банках.

### Парсерні маніфести

`book_manifest.json` пов'язує глави зі сторінками PDF і описами зображень. `<book>/<chapter>/images_manifest.json` надає масив `images`; записи можуть мати `relativePath`, `figureRef`, `page` і метадані розміщення. Публічний шлях зображення має починатися з `/images/`.

### Глосарій і пошук

Глосарій читає масиви з `content/dictionary/terms.json` та `abbreviations.json`; поля запису: `term`, `definition`, `category`. Пошуковий індекс не редагується вручну: `verify_pages_export.mjs` будує `out/search-index.json` з тексту frontmatter/body всіх MDX і сторінкових діапазонів із маніфестів.

## 8. Збірка, запуск і перевірки

### Вимоги

- Node.js, сумісний із Next.js 14 (мінімум 18.17), npm.
- Python 3.10+ та залежності з `requirements.txt` для парсера/генератора.
- Gemini API key потрібен для AI-генерації; парсер, вебсайт і fallback не повинні потребувати ключа.

### Локальна розробка

```bash
npm install
npm run dev
```

Відкрийте адресу, яку надрукує Next.js (типово `http://localhost:3000`). Для Python-операцій створіть/активуйте `.venv` і встановіть залежності:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Перевірки

```bash
npm run verify:quizzes
python -m unittest tests.test_parse_pdf -v
python -m unittest tests.test_generate_content -v
npm run build
```

`npm run build` включає Next.js build, лінт/перевірку типів, створення статичних маршрутів і `postbuild`-перевірку. Postbuild перевіряє metadata уроків, локальність/наявність зображень, усі внутрішні `href`/`src`, відповідність search index сторінкам і рендер квізу в контрольному уроці. `npm run start` є скриптом `next start`, але звичайний production-артефакт цього репозиторію — статичний `out/`; його слід віддавати статичним хостингом.

## 9. Відомий стан і межі перевірки

Під час аналізу в поточному робочому дереві були отримані такі результати:

- `npm run verify:quizzes`: успіх, перевірено 311 питань у 101 JSON-банку.
- `python -m unittest tests.test_parse_pdf -v`: успіх, 43 тести.
- `npm run build`: успіх; згенеровано 100 уроків/112 HTML-сторінок, postbuild перевірив 3 032 зображення та локальні посилання.
- `python -m unittest tests.test_parse_pdf tests.test_generate_content -v`: не може імпортувати модуль генератора. У `scripts/generate_content.py` перед присвоєнням `quiz = "<Quiz />"` у `generate_fallback_mdx` є зайвий відступ, через що Python повідомляє `IndentationError` (рядок 354). Через це недоступні тести генератора і виконання самого скрипту, доки синтаксичну помилку не виправлено.

Перевірки описують поведінку тестового набору та build, але не підтверджують точність згенерованого навчального тексту чи правильність авіаційних відповідей. Контент походить із матеріалів FAA і частково може бути створений мовною моделлю; його необхідно звіряти з першоджерелами. Звіт `out/content-review-report.json` знаходить низку структурних/текстових ознак (наприклад, метадані, кирилицю, пошкоджений OCR/placeholder), але це не є редакторською чи авіаційною сертифікацією.

## 10. Порядок типових змін

### Додати або перевидати посібник

1. Покласти PDF в окремий `resources/library/<Book>/` та налаштувати `chapters.json`.
2. Переконатися, що ім'я папки збігається з book ID у TypeScript і перевірці export.
3. Запустити парсер; переглянути `book_manifest.json`, текст і картинки.
4. Запустити генератор для цієї книги; перевірити/відредагувати MDX та окремі банки квізів.
5. Запустити Python-тести, `npm run verify:quizzes` та `npm run build`.

### Змінити питання або словник

Редагувати JSON-файл за потрібною книгою/главою або словниковий JSON. Для квізу зберігати стабільні унікальні ID й коректний індекс відповіді, потім запускати `npm run verify:quizzes`. Іспитові питання належать до `content/quizzes/ppl/aerodynamics.json`.

### Змінити інтерфейс або механіку

Сторінки та стилі змінюються в `app/`, інтерактивна поведінка — у відповідному компоненті `components/`, моделі/завантаження контенту — у `src/content/`. Після змін перевіряти production build, бо App Router сторінки пререндеряться та експортуються статично.
